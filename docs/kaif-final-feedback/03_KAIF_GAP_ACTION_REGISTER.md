# KAIF Gap and Action Register

## Positive findings

These are demonstrated strengths, not disguised gaps:

- The executive harness elicited a coherent business flow, actors, decision points, failure cases, outcomes, and unknowns for a real brownfield product.
- The agency ladder and least-power guidance supported a proportionate LLM-assisted deterministic workflow rather than an autonomous or multi-agent design.
- The technical harness separated proposal, approval, authorization, execution, result validation, and explanation.
- Direct application interfaces were preferred before MCP, and the design did not require RAG, GraphRAG, long-term memory, a new vector database, or Kubernetes.
- Both harnesses encouraged explicit evaluation gates, human review, rollback, observability, and evidence-linked decisions.
- The clean pilot produced a usable HLD, TDD, handoff, evaluation specification, backlog, and question register without inventing stakeholder answers or financial benefits.

## Primary register

| Gap Area | Reason | Proposed Solution |
|---|---|---|
| G-01: Executable validation spine | The available KAIF repository provides prompt-driven procedures but no shipped validator for required sections, identifiers, references, evidence, or acceptance results. Pilot 2's validators and probes were auditor-authored. | Ship versioned schemas and a CLI/library that validates design artifacts, handoffs, references, decision status, evidence classes, and gate results. Include negative fixtures. |
| G-02: Critical statistical fidelity gates | Generic model scores and a 98 percent parameter target are not sufficient where a changed dependent variable, fixed effect, cluster, or covariance invalidates the analysis. | Add a domain-critical field class with 100 percent exact preservation gates and independent numerical fixtures for supported statistical methods. |
| G-03: Machine-checkable HLD-to-TDD contract | Stable requirement and decision IDs were created manually. The repository does not enforce complete HLD-to-TDD transfer. | Publish a canonical handoff schema and reject missing, duplicate, unresolved, or orphaned requirements, decisions, risks, assumptions, and approvals. |
| G-04: Single workflow registry | Pilot 2 found a next-step instruction in model selection that conflicts with the central harness order and can skip later design steps. | Generate skill routing from one versioned workflow registry and test every next-step link against the canonical sequence. |
| G-05: Platform applicability | Technical output standards require Kubernetes-specific material even when the application already has a suitable managed-container deployment and no measured cluster need. | Make platform questions conditional. Accept evidence for the current deployment and require Kubernetes controls only when a recorded trigger applies. |
| G-06: Framework and model neutrality | Some skills contain categorical framework preferences or benchmark defaults without workload-specific evidence. | Add an explicit existing-code option, date all comparative evidence, label unknown scores, and require measured task outcomes before migration recommendations. |
| G-07: Guard, identity, evaluation, deployment, platform, and value modules | Six named modules were described but not implemented in the authorized KAIF repository. Design vocabulary must not be mistaken for callable controls. | Publish each module as a separately versioned, testable capability or clearly label it as roadmap-only. Start with guard/identity deny tests and the evaluation validator. |
| G-08: Business-value and efficacy evidence | Neither pilot measured adoption, time to correct result, review effort, cost per correct result, or improvement over ordinary review. | Run a matched, frozen-snapshot study with and without KAIF. Blind the outcome review and measure correctness, false positives, actionability, traceability, elapsed effort, and review burden. |
| G-09: Knowledge and license provenance | The audit found incomplete repository-level license and third-party corpus rights evidence. It did not establish infringement. | Add an explicit repository license plus a provenance and permitted-use record for every bundled third-party corpus. Obtain rights review where needed. |
| G-10: Checkpoint and journal enforcement | Gate disposition and journal completeness depend on the orchestrator. Routine checkpoint prompts can also conflict with authorized autonomous execution. | Record authority, gate disposition, evidence, and defer reasons in a machine-checkable journal without forcing redundant confirmations. |
| G-11: Brownfield source-state and contamination control | Both pilots needed user-authored rules to freeze source identity, separate outputs, ignore later untracked files, and stop on source changes. KAIF does not provide a reusable clean-run protocol. | Add a brownfield run manifest with repositories, commits, dirty-state qualification, prohibited paths, output roots, source-change detection, and contamination attestations. |
| G-12: Evidence profiles for design, integration, browser, and production claims | The pilots carefully separated design evidence from runtime proof, but this separation is not enforced by a shared KAIF evidence model. | Define evidence profiles and claim rules. A design pass must not satisfy integration, browser, deployment, user acceptance, or production gates without the required artifacts. |

## Severity summary

These severities describe KAIF/framework roadmap priority within the feedback package. They are not incident severities for the current ProfSur application. In particular, a P0 KAIF gap does not automatically make a ProfSur defect P0; ProfSur repair priority is tracked separately in the Pilot 2 developer action plan.

| Severity | Count | Meaning in this register |
|---|---:|---|
| P0 | 2 | Blocks credible executable validation for safety-critical statistical use cases. |
| P1 | 8 | Material framework, governance, evidence, or applicability gap. |
| P2 | 2 | Important consistency or usability improvement that does not block sharing this pilot. |
| P3 | 0 | No editorial-only gap retained after consolidation. |
