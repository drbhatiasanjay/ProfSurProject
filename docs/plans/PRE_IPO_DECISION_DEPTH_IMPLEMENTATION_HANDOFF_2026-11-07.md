# Pre-IPO decision-depth implementation handoff

Date: 7 November 2026. Branch: codex/pre-ipo-decision-depth. Base: 568747832cd06e3721d3deda185df8b72918b4d2.

This is an additive, separately reviewable implementation of the supported deterministic domains of the decision-depth PRD. It is not a claim that the complete Pre-IPO production acceptance programme or empirical calibration is finished.

## Integration boundary

The only existing application file changed is pages/27_pre_ipo_drhp.py: a workspace selector immediately after page configuration. Existing Pre-IPO terminal remains the default. The new mode calls components/pre_ipo_decision_workbench.py and stops before legacy calculations/CSS.

Antigravity can retain its fixes to the existing terminal, ingestion, schema, model registry and deck. Preserve the new selector when resolving the page merge. No existing terminal, dataset, authentication policy, sidebar registry, manuscript, Stata engine or existing deck generator is replaced. Do not overwrite Antigravity's uncommitted files with this worktree.

## User workflow

1. Authenticate at the root app and open Pre-IPO DRHP Intelligence using its registered sidebar entry.
2. Select Decision-depth workbench. Choose a presentation perspective.
3. Enter company context once, import case JSON, inspect/import an existing registry dossier, or restore an owned historical revision.
4. Inspect extracted attributes. Registry values remain unverified; no CMIE completeness claim appears without a versioned supplied reference.
5. Add dated source records through the evidence form. Accepted means the user's review judgment, never independent verification.
6. Choose optional analyses and apply named model inputs. Scalar values have individual form fields; nested events, scenarios and security terms retain structured JSON. Unspecified models remain explicitly unavailable.
7. Run the assessment. Review the question, calculation mechanism, result, evidence status, assumptions, next action and methodology references.
8. Save a private immutable revision. Record a decision/rationale against that revision. Repeated identical action submissions deduplicate; original revisions remain inspectable.
9. Download JSON and a paginated PPTX from the exact displayed report snapshot. Downloads do not trigger reruns.

## Algorithm coverage and supported domains

| PRD algorithm | Implementation | Supported domain / limit |
|---|---|---|
| ALG01 | evidence.py | Public availability vs actual recorded access, withdrawal, eligible supersession, origin families, semantic comparison and supplied reconciliation bridges. No independent verification or automatic source authority ranking. |
| ALG02 | evidence.py | Falsifiable propositions with all/any evidence dependencies; missing is not supported; disputed evidence remains disputed. No causal inference. |
| ALG03 | financial.py | Capacity-constrained price/volume/cost model, revenue reconciliation and frozen-cohort retention. Generic industrial driver model; sector-specific operating templates and connected three-statement forecasting are further work. |
| ALG04 | financial.py | Dated ordered cash events, documented conditional facilities, interim deficits, CFO/interest/tax bridge and explicit illustrative loss-use policy. Net supplied event timestamps; intra-event timing and jurisdictional tax-law validation are not modeled. |
| ALG05 | financial.py | Ordinary fixed-price primary raise, fees, dilution and aggregate EV-to-equity cash/debt conservation. Circular pricing, option grants, complex conversion rights and per-holder old/new value allocation are unsupported. |
| ALG06 | financial.py | Claim/rate/currency/real-nominal matching, terminal reinvestment, discounted value and residual-checked bracketed reverse DCF. One growth variable, fixed rate/terminal assumptions; financial institutions blocked from generic industrial models. No global root uniqueness claim. |
| ALG07 | financial.py | Finite coherent admissible shock frontier with declared scales/weights. Scenario margins are supplied, not generated by an integrated economic simulator. No global minimum or likelihood claim. |
| ALG08 | assessment.py | Mandatory blockers and decision-outcome/hurdle sensitivity; optional explicit-prior joint-signal EVPI/EVSI with cost/delay. No invented probabilities. |
| ALG09 | assessment.py | Explicit common context and paired-scenario partial dominance. The caller must declare the relevant context dimensions; no universal opportunity score. |
| ALG10 | assessment.py + store.py | Original commitment snapshot, maturity/comparability checks, separate observations and append-only case revisions. No management honesty score or scraped forecast history. |
| ALG11 | assessment.py + store.py | Missing/stale/disputed states, lower-bound threshold hysteresis, observation-ID dedup and revision lineage; action dedup. No live disclosure feed, scheduler or external alerts. |
| ALG12 | financial.py | Exact symmetric price attribution, dated ACT/365 NPV, distribution-only MOIC and bounded multi-root IRR search. Nonconventional flows remain ambiguous; no exhaustive root guarantee. |
| ALG13 | financial.py | Supplied reviewed nonparticipating terms with fixed joint conversion elections and seniority/pari-passu preference allocation. Unsupported participation/strategic elections fail explicitly. Input shares must be on the declared as-converted basis. |
| ALG14 | assessment.py + data_quality.py | Finite structural variant envelope, source-family dependence labels and explicit econometric/ML eligibility gates. No calibrated Monte Carlo, CI, default probability or production predictive model. |

Case reports are independent snapshots: model inputs are supplied explicitly, not silently pulled from legacy dossier constants. Applying any source/input change invalidates the current workbench report. Earlier saved versions remain unchanged. New external source arrivals are not automatically polled.

## Source and empirical evidence contract

Methodology references are carried in the report and deck separately from issuer source records. They support method choices, not the issuer's inputs or the application's empirical validity. Reviewed source IDs do not assert that every numeric model input has been mapped and verified.

Attribute inventory accepts a versioned reference and exact attribute IDs; null, zero, disputed and unmapped fields remain distinct. Existing dossier import flattens the stored attributes for inspection without upgrading provenance or declaring the registry a verified extraction.

Panel regression, dynamic panel GMM and predictive ML are not automatically run on a few issuer observations. Eligibility contracts return insufficient-data or design/validation-review states. No existing Stata capability is removed or falsely described as executed.
