Create the GitHub Actions CI/CD pipeline that automatically runs the full test suite on every push to master and deploys to Cloud Run only when tests pass.

Output: `.github/workflows/deploy.yml` with two jobs — `test` (pytest on Python 3.11) and `deploy` (Cloud Run, gated on test success). The GCP service account setup is a manual step documented as a checkpoint.

<task type="auto">
  <name>Task 1: Create .github/workflows/deploy.yml with test + deploy jobs</name>
  <files>.github/workflows/deploy.yml</files>
  <action>
Create the directory `.github/workflows/` and write `deploy.yml` with the following structure:

```yaml
name: Test and Deploy

on:
  push:
    branches: [master]
  pull_request:
    branches: [master]

jobs:
  test:
    name: Run pytest (Python 3.11)
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - name: Set up Python 3.11
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"
          cache: "pip"

      - name: Install dependencies
        run: |
          pip install --upgrade pip
          # Install torch CPU-only first (matches Dockerfile pattern, avoids 2GB GPU wheel)
          pip install torch --index-url https://download.pytorch.org/whl/cpu
          pip install -r requirements.txt
          pip install pytest

      - name: Run tests
        run: |
          python -m pytest tests/ \
            --ignore=tests/smoke_auth.py \
            --ignore=tests/smoke_phase1.py \
            -v --tb=short
        env:
          # Disable CMIE so tests don't need secrets.toml
          ENABLE_CMIE: "false"

  deploy:
    name: Deploy to Cloud Run
    runs-on: ubuntu-latest
    needs: test
    if: github.ref == 'refs/heads/master' && github.event_name == 'push'

    steps:
      - uses: actions/checkout@v4

      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v2
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Set up Cloud SDK
        uses: google-github-actions/setup-gcloud@v2

      - name: Deploy to Cloud Run
        run: |
          gcloud run deploy lifecycle-leverage \
            --source . \
            --region us-east1 \
            --project tempproject-462219 \
            --port 8501 \
            --memory 2Gi \
            --allow-unauthenticated \
            --quiet
```

IMPORTANT implementation notes:
- `needs: test` is what gates deploy on test success — do not omit it.
- `if: github.ref == 'refs/heads/master' && github.event_name == 'push'` ensures PRs run tests but do NOT trigger deploy.
- `ENABLE_CMIE: "false"` prevents test failures from missing secrets.toml in CI environment.
- torch is installed from CPU wheel URL to match the Dockerfile pattern and avoid the 2GB GPU wheel timing out the CI runner.
- `google-github-actions/auth@v2` and `google-github-actions/setup-gcloud@v2` are the current stable versions (2024).
- The `--source .` deploy uses Cloud Build (same as manual deploy command), which reads `.gcloudignore` — secrets.toml is already carved back in there via `!.streamlit/secrets.toml`.

<task type="checkpoint:human-action">
  <name>Task 2: Create GCP service account and store credentials as GitHub secret GCP_SA_KEY</name>

  <what-needed>
GitHub Actions needs a GCP service account key to authenticate `gcloud run deploy`. This cannot be automated — it requires GCP Console + GitHub UI steps that Claude cannot perform (no browser session, no GitHub OAuth).
  </what-needed>

  <how-to-complete>
**Step A — Create the service account (GCP Console or Cloud Shell):**

1. Open https://console.cloud.google.com/iam-admin/serviceaccounts?project=tempproject-462219
2. Click **+ CREATE SERVICE ACCOUNT**
3. Name: `github-actions-deploy`
4. Description: `GitHub Actions Cloud Run deployer`
5. Click **CREATE AND CONTINUE**
6. Assign these roles (click **+ ADD ANOTHER ROLE** for each):
   - `Cloud Run Admin` — deploys the service
   - `Storage Admin` — Cloud Build uploads source to GCS
   - `Cloud Build Editor` — submits the build
   - `Service Account User` — allows the SA to act as the Cloud Run runtime SA
7. Click **DONE**

**Step B — Download the key JSON:**

1. In the service accounts list, click `github-actions-deploy`
2. Go to the **KEYS** tab
3. Click **ADD KEY → Create new key → JSON**
4. Save the downloaded `.json` file (keep it safe — treat like a password)

**Step C — Add the key as a GitHub secret:**

1. Open https://github.com/drbhatiasanjay/ProfSurProject/settings/secrets/actions
2. Click **New repository secret**
3. Name: `GCP_SA_KEY` (exact — the workflow references this name)
4. Value: paste the ENTIRE contents of the downloaded JSON key file
5. Click **Add secret**

**Step D — Enable required GCP APIs (if not already enabled):**

Run in Cloud Shell or local terminal (one-time):
```bash
gcloud services enable \
  run.googleapis.com \
  cloudbuild.googleapis.com \
  containerregistry.googleapis.com \
  --project=tempproject-462219
```

**Verification after completing steps A-D:**
- The secret `GCP_SA_KEY` should appear in https://github.com/drbhatiasanjay/ProfSurProject/settings/secrets/actions
- The service account `github-actions-deploy` should appear in https://console.cloud.google.com/iam-admin/serviceaccounts?project=tempproject-462219
  </how-to-complete>
